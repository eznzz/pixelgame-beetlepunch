# BEETLE BRAWL

**STANCE CRIME / STANCE CRIMEA · v0.1.12 · SCENE v2.8**

Браузерная двухмерная пиксельная аркада с защитой автомобиля, бесконечными волнами противников, возрастающей сложностью и таблицей рекордов. Игра рассчитана на ПК и мобильные устройства.

Этот README фиксирует существующую реализацию из `stance-crimea-menu-v4-game-beetle-v0.1.7-updated.zip`, каталог `stance-crimea/game-beetle/`. Название STANCE CRIME используется как название проекта, STANCE CRIMEA сохранено в исходных заголовках и ключах хранения. Документ предназначен для самостоятельного репозитория игры; исходный код этим документом не изменяется.

## 1. Концепция и сюжет

Глубокой ночью, накануне автомобильного фестиваля, вы организовали выставку редких автомобилей. Но едва всё было готово, любопытные зеваки потянулись к белому Volkswagen Beetle.

Защитите редкий экспонат от незваных гостей. Не дайте им прикоснуться к автомобилю!

Игрок перемещается по горизонтальной арене, отбивает приближающихся с двух сторон противников, набирает очки и старается продержаться как можно дольше. Уровней и финальной победы в текущей реализации нет. Партия заканчивается при нуле жизней.

## 2. Технологии и запуск

- HTML5 Canvas 2D, JavaScript без внешнего игрового движка, CSS.
- Python 3 (стандартная библиотека) для сборки ресурсов и автономной версии.
- Node.js для автоматических тестов симуляции и рекордов.
- PHP 7.4+ (предпочтительно поддерживаемая версия 8.x) для общего рейтинга; необязателен для самой игры.
- Нет npm-зависимостей, обязательного сетевого подключения для автономной версии.

Открыть `index.html` либо `game-beetle-v0.1.12-play.html` в современном браузере. Для разработки рекомендуется запускать локальный сервер из корня каталога игры:

```sh
python -m http.server 8000
```

Открыть http://localhost:8000/. Для проверки общего рейтинга вместо Python-сервера запустить:

```sh
php -S 127.0.0.1:8000
```

## 4. Архитектура движка

### 4.1 Симуляция (`engine.js`)

`BeetleEngine(config, scene, sprites, rng = Math.random)` не зависит от DOM, Canvas и браузерного ввода. Координаты измеряются в пикселях исходной сцены, время — в секундах. Подстановка RNG позволяет воспроизводить сценарии тестов.

Основные методы:

| Метод | Назначение |
|---|---|
| `reset()` | Сброс партии, героя, таймеров, врагов, эффектов и предметов |
| `step(dt, input)` | Один шаг симуляции (`left`, `right`, `punch`) |
| `pause()` / `resume()` | Управление остановкой игрового времени |
| `spawn(side, type)` | Создание противника с выбранной стороной и типом |
| `startPunch()` / `impact()` | Начало атаки и однократное разрешение попадания |
| `dropItem(enemy)` | Однократный розыгрыш предмета после поражения |
| `advanceItems(dt, oldX)` | Старение, подбор, применение предметов |
| `vanish(enemy)` / `advanceVanish(dt)` | Удаление и эффект распада |

Состояние включает `hero`, `enemies`, `items`, `effects`, `vanishEffects`, `itemEffects`, `lives`, `score`, `time`, таймер появления врагов. Геометрия столкновений одномерная по X; физического движка, прыжков и гравитации нет.

### 4.2 Игровой цикл (`game.js`)

`requestAnimationFrame` → ограничение реального delta time до 0.08 с → аккумулятор → шаги симуляции по 1/120 с → обновление интерфейса → рендер. Игровое время не продвигается вне `playing`. Небо имеет отдельные часы и обновляется с частотой 12 FPS. Скрытие вкладки или потеря фокуса ставят активную игру на паузу.

Анимация рассчитывается по `Math.floor(age * anim.fps)`; цикличные последовательности используют остаток от числа кадров, нецикличные — последний кадр. Скорость движения не влияет на FPS анимации.

### 4.3 Состояния

```text
menu → info → playing ↔ paused
                ↓
               over → ввод имени → TOP 10
                ↓                  ↓
              заново             menu
menu ↔ records
```

`ending` — производное UI-состояние при `over`, пока проигрывается финальный распад, а не отдельное состояние симуляции. Незавершённая партия не отправляется в рейтинг. Выход на основной сайт сейчас ведёт на `../index.html`.

## 5. Игровые механики

### Герой

- Старт X = 832; границы перемещения 48…1616.
- 5 начальных и максимальных жизней.
- Скорость 395 px/s. Встречные направления взаимно компенсируются.
- Направление фиксируется при начале удара. Во время удара движение останавливается.
- Удар не повторяется автоматически при удержании пробела или зоны касания.

### Противники

Четыре типа (`enemy-01`…`enemy-04`) появляются за левой или правой границей сцены и бегут к белому Beetle. Автоматический выбор не допускает более двух последовательных появлений с одной стороны; повторы типа вероятностно уменьшаются. Скорость и частота появления растут со временем; часть противников получает случайное ускорение. FPS бега всегда 12.

Цели касания: X = 665 слева и 1009 справа. Враг начинает анимацию `touch`, отнимает жизнь на кадре с индексом 2, затем исчезает с эффектом распада. Одно касание — одна жизнь, без очков и выпадения предмета. После зарегистрированного касания враг уже не является целью удара.

### Удар

На третьем кадре `punch` (индекс 2, примерно 0.167 с после начала) выполняется `impact()`. Направленное расстояние: `(target.x - hero.x) * attack.dir`. Допустимый диапазон от −10 до 118 px включительно. Из врагов выбирается ближайший допустимый, ещё не поражённый и не коснувшийся машины. За него начисляется 100 очков, запускаются `hit` и PUNCH FX, отбрасывание на 95 px. После окончания `hit` враг удаляется, однократно разыгрывается выпадение. Промах не создаёт PUNCH FX. Счёт ограничен 999999.

### Предметы

| ID | Внешний вид | Эффект |
|---|---|---|
| `bottle` | Зелёная бутылка | −1 жизнь |
| `apple` | Яблоко | +1 жизнь |
| `cigarettes` | Пачка сигарет | −1 жизнь |
| `banana` | Жёлтый изогнутый банан с коричневым хвостиком | +1 жизнь |

Шанс выпадения — 10% на побеждённого врага, один предмет, четыре равных веса (по 25% условно при выпадении). Предмет появляется на финальной позиции врага с ограничением границ арены. Живёт 5 секунд **игрового** времени, мигает в последнюю секунду. Подбирается автоматически при прохождении в пределах 30 px, включая пересечённый за шаг отрезок движения. Жизни ограничиваются диапазоном 0…5; полезный предмет расходуется и при полном здоровье (+0). Вредный предмет способен завершить партию. Очки за подбор не начисляются.

**Уничтожение предметов (v0.1.7):** на кадре попадания удаляются все существующие предметы в зоне удара, независимо от наличия врага. Для каждого создаётся PUNCH FX; очки и жизни не меняются. Один удар может уничтожить несколько предметов и победить одного противника. Пока идёт замах, автоматический подбор предметов внутри зоны атаки откладывается до попадания. Выпавший позже предмет не уничтожается ретроактивно этим же ударом.

Все параметры ниже взяты из `config.js` версии 0.1.6. Изменять баланс централизованно, не дублировать значения в рендере.

| Параметр | Значение | Назначение |
|---|---:|---|

| `touchLeft` / `touchRight` | 665 / 1009 | Координаты касания машины |
| `vanishDuration` | .38 | Эффект распада, с |
| `itemDropChance` | .10 | Шанс выпадения |
| `itemLifetime` / `itemPickupRadius` | 5 / 30 | Время, с / радиус, px |

| `fixedStep` | 1/120 | Шаг симуляции, с |
| `skyClouds` / `retroMode` | true / retro | Облака и режим сцены |

Формулы текущего баланса:

```js
base = Math.min(enemyMaxSpeed, enemySpeed + time * enemySpeedGain)
       * (0.93 + type * 0.04); // type: 0..3
fastProbability = Math.min(fastChanceMax, fastChance + time * fastChanceGain);
spawnDelay = Math.max(spawnMin, spawnInterval - time * spawnRamp)
             * (1 + (rng() - 0.5) * 2 * spawnJitter);
```

`enemyMaxSpeed` и `spawnMin` не являются строгими пределами итоговых значений после модификаторов. Сохранять это поведение при рефакторинге, если баланс явно не пересматривается.

## 7. Управление и адаптация

| Действие | ПК | Сенсорный экран |
|---|---|---|
| Влево | ← | 0–20% ширины viewport |
| Вправо | → | 20–40% |
| Удар | Space | 40–100% |
| Пауза | Escape | Кнопка паузы |

Невидимые зоны занимают весь viewport, включая поля вокруг арены. Используются Pointer Events, `pointerId`, захват указателя и независимая карта касаний. Мультитач: удержание направления и удар другим пальцем. Очистка ввода при отпускании/отмене касания, потере захвата, фокуса и смене состояния. Кнопки интерфейса выше зон по z-index. Определение мобильного управления по `any-pointer: coarse` или `navigator.maxTouchPoints > 0`, поэтому гибридный ПК может получить сенсорный интерфейс.

Не возвращать видимые стрелки и красную кнопку удара без отдельного согласования. Не использовать глобальное блокирование ввода, мешающее полю имени. На игровых поверхностях отключены `user-select`, `-webkit-tap-highlight-color`, `-webkit-touch-callout`, drag, `contextmenu`, `selectstart`; у поля имени восстановлено выделение текста.

Арена всегда 16:9, вписывается в viewport без растяжения. Рекомендуемая ориентация телефона — горизонтальная; портретная поддерживается с полями. Заставка загрузки, напротив, занимает весь viewport (`position: fixed; inset: 0; background-size: cover; background-position: center`) и обрезается без пустых полос. Ресурс — `assets/scene/loading-background.webp`.

Экран информации: исходное пиксельное описание, шрифт 4 единицы на ПК и 5 на сенсорном экране (+25%), перенос 42/34 символа соответственно, пустой интервал перед мобильной подсказкой. Подсказка мобильного управления не рисуется на обычном ПК.

## 8. Визуальный стандарт

Ночная автомобильная выставка в пиксельной ретро-стилистике. Белый Volkswagen Beetle — единственная защищаемая цель; Москвич-412 и ВАЗ-2103 — статичные декоративные экспонаты без коллизий. Сохранять утверждённые композицию, цвета, пропорции и силуэты. Не заменять ретро-графику векторной или сглаженной без отдельного решения.

- Сцена 1664×936, линия земли Y=776, центр машины X=832.
- Canvas без сглаживания (`imageSmoothingEnabled=false`), CSS `image-rendering: pixelated`.
- Порядок слоёв: background → plaza → shadow → barrier-rear → beetle → barrier-front → characters (сначала предметы) → effects → foreground → hud.
- Фон: яркость/контраст/насыщенность 88/95/85%; приглушение тёплых бликов 25%. Персонажи 110/120/90%, ночное затемнение 10%; машина и ограждения 108/110/112%, затемнение 17%. Луна защищена маской; контрастная опорная точка фона 52/255.
- Режимы фона: normal (1 px), retro (4 px, 64 цвета на слой, по умолчанию), arcade (8 px, 32 цвета на слой). Упрощение применяется только к фону, площади и переднему плану. Цветовые коррекции выполняются программно без перезаписи оригинальных PNG.
- Медленно движущиеся облака, обновление неба 12 FPS; звездопад исключён из актуальной SCENE v2.8.
- UI: пиксельные буквы 5×7, ступенчатые панели, ночные сине-фиолетовые оттенки, тёплый светлый текст. Основные цвета: `#111b2b`, `#211936`, `#69435f`, `#e6d9ed`, `#fff0dc`.

### Спрайты и анимации

Кадр персонажа 80×64 px, опора (40,59), базовое направление вправо, зеркалирование влево, масштаб отображения ×3. Прозрачный фон, чёткие тёмные контуры. Метаданные в `assets/sprites.json`.

| Сущность / анимация | Кадры | FPS |
|---|---:|---:|
| hero idle | 4 | 5 |
| hero run | 6 | 12 |
| hero punch | 4 | 12 |
| enemy run (все четыре типа) | 6 | 12 |
| enemy touch | 4 | 10 |
| enemy hit | 3 | 10 |
| PUNCH FX | 6 | 18 |

PUNCH FX: кадр 64×64, опора 32×32, масштаб ×2, около 333 мс, без повтора. Предметы: PNG RGBA 24×24, отображение 48×48. Банан должен иметь узнаваемую жёлтую дугу и коричневый хвостик. Не менять FPS бега при изменении скорости перемещения. Старые изображения мобильных кнопок в `assets/hud/mobile/` — архивные, не используемые в текущем UI.

## 9. Рекорды и хранение данных

После GAME OVER обязательный ввод имени (1–16 символов: кириллица, латиница, цифры, пробел, дефис), нормализация в верхний регистр. Результат отправляется после подтверждения. TOP 10 сортируется по убыванию SCORE, при равенстве — по возрастанию UTC-даты и ID. Текущий результат подсвечивается, если попал в десятку.

- `records.js`: `BeetleRecords`, `rankRecords`, `normalizeRecordName`, запросы GET/POST к `records.php`, таймаут 3500 мс.
- `records.txt`: UTF-8 TSV, поля `RANK`, `SCORE`, `DATE`, `RUN_ID`, `NAME`. Старые записи без имени читаются как «ИГРОК». Файл блокировки и атомарная замена требуют права записи каталога для PHP.
- Локальный TOP 10: `stance-crimea.game-beetle.top10.v1`; личный лучший счёт: `stance-crimea.game-beetle.best.v1`.
- При отсутствии PHP — локальный рейтинг, при запрете localStorage — память страницы. Локальные результаты автоматически не синхронизируются с сервером.
- Серверный рейтинг не защищён от накрутки: результат поступает от клиента. Не считать его доверенным соревновательным сервисом.
- Не перезаписывать живой `records.txt` при релизах и не публиковать реальные записи пользователей в Git. Не устанавливать права 777.

## 10. Сборка и тестирование

Из корня игры:

```sh
python build.py
node --test tests/*.cjs
```

`build.py` читает JSON сцены и спрайтов, собирает PNG в Base64 в `game-data.js`, встраивает CSS/JS и WebP-фон заставки в `game-beetle-v0.1.12-play.html`. После изменения любых ресурсов, конфигурации или кода пересобрать автономную версию. Имя выходного HTML сейчас задано в сборщике явно; при выпуске новой версии обновить его и заголовки.

Тесты: `engine.test.cjs`, `variation.test.cjs`, `items.test.cjs`, `records.test.cjs`. Все четыре набора повторно запущены на исходниках v0.1.7 при подготовке README — успешно.

Чек-лист ручной регрессии перед выпуском:

- [ ] ПК: движение, удар, пауза, имя, рейтинг, рестарт.

## 11. Создание отдельного Git-репозитория (рекомендация)

1. Скопировать содержимое `game-beetle/` из актуального архива в новый каталог. Добавить этот README.
2. Выбрать имя репозитория, например `stance-crime-game-beetle`. Проверить права на все изображения перед публикацией; лицензия в текущем архиве не установлена, не добавлять её произвольно.
3. В самостоятельном размещении пересмотреть `home()` в `game.js`: `../index.html` предполагает наличие основного сайта. Определить адрес выхода либо явно отключить этот пункт для standalone.
4. Подготовить `.gitignore`, например:

```gitignore
__pycache__/
*.pyc
.DS_Store
records.txt
records.txt.lock
```

Для чистой установки рейтинга можно сохранить отдельный пустой шаблон `records.example.txt` с заголовком исходного TSV и описать его копирование в `records.txt`. Проверить фактические имена временных серверных файлов перед добавлением дополнительных исключений.

5. Решить, хранить ли сгенерированные `game-data.js` и offline HTML в Git. Для начала рекомендую сохранить `game-data.js` (нужен `index.html`) и публиковать автономный HTML вместе с релизами. Не удалять сборку, пока не настроен процесс сборки и публикации.

```sh
git init -b main
git add .
git commit -m "Initial BEETLE BRAWL v0.1.7 baseline"
git tag v0.1.7
```

После создания удалённого репозитория использовать его реальный URL для `git remote add origin` и `git push -u origin main`, затем `git push origin v0.1.7`. Репозиторий автоматически этим README не создаётся. GitHub Pages подходит для статической игры и локального рейтинга, но не исполняет PHP; общий рейтинг потребует другого сервера.

## 12. Правила дальнейшего развития

1. Не смешивать логику симуляции, графический рендер, DOM-ввод и сетевое хранение. Сохранять возможность тестирования движка вне браузера.
2. Новые параметры механик добавлять в `config.js`, графические метаданные — в JSON, исходные изображения — в тематические каталоги.
3. Сохранять независимость скорости движения и FPS анимации, фиксированный шаг, однократность попаданий и выпадений.
4. Не менять утверждённую ночную композицию, размеры арены, управление, баланс и формат рекордов без явного задания.
5. При добавлении новых предметов согласовывать ID, вес, эффект и спрайт; проверять подбор, истечение, уничтожение и границы жизней.
6. При изменении движка обновлять автоматические тесты. При изменении UI проверять ПК и обе ориентации телефона.
7. Хранить оригиналы графики и воспроизводимую сборку. Не редактировать сгенерированный HTML вручную вместо исходников.
8. Версионировать релизы, фиксировать изменения и не затрагивать основной сайт при работе только над игрой.

Использовать README вместе с актуальными исходниками игры как стартовый контекст. Сначала проверять файлы, относящиеся к задаче; не реконструировать проект по одному описанию, если доступен код. Вносить только согласованные изменения, сохранять стилистику и существующую механику, запускать тесты, пересобирать автономный HTML и явно сообщать о непроверенных сценариях.
